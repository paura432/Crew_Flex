# Visual parity

Reference: S1 `CrewFlex_v1.1.html` rendered with headless Chromium (file://), 1440×900 and 390×844,
every role/tab (36 captures, 0 px horizontal overflow, 0 console errors). Current app: deployed
`https://crew-flex.vercel.app` public routes at 1440/1024/768/390 (0 overflow, 0 console errors except the
expected 404 for an unknown route), and local rendering for authenticated screens (no production
credentials; sign-up needs e-mail confirmation). Evidence in `evidence/` (JPEG, 1440 wide; 390 for the
three screens that matter most for this slice).

Design tokens already match S1: navy `#0c2137`, ink `#172c44`, accent `#ff982f`, canvas `#f5f7fa`, muted,
ok/warn/danger, Inter. S1 additionally uses **Outfit** for display headings (Google Fonts) — not adopted
(self-hosted Inter only; P2).

reference remains S1 and every row below is unchanged. No screen was modified in this phase.

## Documented exceptions to pixel parity

- Spanish copy is not reproduced (OD C-5); labels are translated 1:1 where the screen exists.
- Google Fonts (Inter + Outfit) are not loaded from a CDN; Inter is self-hosted through `next/font`.
- S1's demo chrome (role select, demo banner, reset) is intentionally not reproduced.
- Day-cell click semantics: S1 toggles a per-day state in local state; the current model stores UTC
  windows. A day click creates/updates/deletes a one-day window; days covered by a longer window are
  shown as covered and edited through the windows panel (no silent splitting of windows).
