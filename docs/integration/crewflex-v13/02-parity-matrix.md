# 02 · Parity matrix — CrewFlex V1.3 vs Next/Supabase

> Phase 0.8 (2026-10-15). Complements `docs/audit/PARITY_MATRIX.md`, which compared V1.1 HTML,
> the blueprint and recovered sources (88 rows) and **never looked at V1.3**. IDs here are `V13-*`.
> Evidence for every `IMPLEMENTED_AND_VERIFIED` row is in `07-validation-evidence.md`.

**Legend**

- **Env** (where V1.3 demonstrates it): `D` demo (IndexedDB, simulated identity) · `S` beta server
  (Node/SQLite, real accounts) · `T` tools (no server) · `—` absent from V1.3.
- **Next status**: `IMPLEMENTED_AND_VERIFIED` (executable evidence this phase) · `IMPLEMENTED_UNVERIFIED`
  · `PARTIAL` · `MISSING` · `DEMO_ONLY` (V1.3 only simulates it; nothing real to port) ·
  `NOT_APPLICABLE` · `BLOCKED_BY_DECISION`.
- **Prio**: P0 blocks the core loop (passport → qualifications → availability → capacity → matching) ·
  P1 next block · P2 later · P3 out of V1.
- Paths: V1.3 relative to `CrewFlex-v1.3/`; Next relative to the repo root. EF = Edge Function.
- Data model column is folded into "Next equivalent" (tables in `snake_case`).
